01 / El propósito

Una biblioteca para construir.

Esta página está pensada para ayudarte a crear códigos usando ejemplos, explicaciones y advertencias sobre su funcionamiento. Puedes consultar el catálogo, comparar soluciones y adaptar lo que encuentres a un proyecto propio. No necesitas empezar siempre desde una hoja en blanco: leer un ejemplo pequeño y comprender cada parte también es una forma de aprender a programar.

Una biblioteca de código es una colección de referencias. Cada ficha te orienta sobre un script, su lenguaje, sus requisitos y el entorno en el que se espera utilizarlo. Algunos ejemplos sirven para interfaces web; otros se relacionan con Lua, Roblox Studio o juegos concretos. Que dos códigos estén en la misma biblioteca no significa que se ejecuten de la misma manera.

RCC reúne esas referencias para facilitar la búsqueda y la experimentación. Su objetivo es acompañarte mientras construyes y modificas código. Los ejemplos necesitan revisión y adaptación; copiarlos no garantiza que resuelvan cualquier idea ni que funcionen en todos los dispositivos.

02 / Tu proceso

De una idea a algo que funciona.

Empieza escribiendo qué quieres conseguir: mostrar un menú, organizar datos, cambiar una interfaz o crear una mecánica para tu propio juego. Cuanto más concreta sea la idea, más fácil será elegir un ejemplo útil. Busca por nombre o etiqueta y revisa la descripción de la ficha antes de copiar.

  1. Elige el entorno. Decide si trabajas en una página web, en Roblox Studio o con un intérprete Lua. Java y JavaScript son lenguajes diferentes; el nombre parecido no los hace intercambiables.
  2. Lee el código y sus requisitos. Identifica las entradas, los resultados esperados, las dependencias y las partes que necesitas configurar. Comprueba si el ejemplo requiere archivos, objetos del juego o permisos específicos.
  3. Guarda una copia y cambia una cosa cada vez. Usa un proyecto de prueba. Conserva una versión que funcione y anota qué modificas para localizar los errores con más facilidad.
  4. Comprueba el resultado. Prueba los casos normales y también entradas vacías, valores inesperados y diferentes tamaños de pantalla cuando corresponda. Lee los mensajes de error antes de añadir más cambios.

Crear código también consiste en quitar lo que sobra, dar nombres claros y explicar las decisiones. Cuando entiendas un ejemplo, intenta reconstruir una versión sencilla con tus propias palabras y comentarios. Así conviertes una referencia de la biblioteca en conocimiento que puedes reutilizar.

03 / Explora con criterio

Herramientas que acompañan la lectura.

El catálogo permite abrir fichas, copiar códigos y consultar los datos disponibles de cada referencia. Después de copiar, el acceso «¿Qué hace este código?» te lleva al Laboratorio con ese contenido. También puedes entrar en la sección de prueba y pegar un fragmento para analizarlo.

El análisis del Laboratorio utiliza reglas locales que buscan patrones conocidos. Puede orientar sobre el lenguaje y algunos usos probables, pero no ejecuta el código, no demuestra que sea seguro y no entiende todas las variantes posibles. Un resultado desconocido o una clasificación incorrecta requiere revisar el texto y la documentación del lenguaje.

El generador de ofuscador ofrece transformaciones para Lua/Luau y Java. La ofuscación cambia la presentación del código y puede dificultar su lectura, pero no es cifrado ni una garantía de protección. Conserva siempre el original legible y comprueba la salida en su entorno antes de usarla en un proyecto importante.

04 / Lee antes de ejecutar

Advertencias para usar la biblioteca.

La presencia de un código en el catálogo no equivale a una revisión completa. Consulta su estado de verificación y sus referencias. Una comprobación de sintaxis no demuestra que un script haga lo esperado, sea compatible con tu entorno o esté libre de errores.

Contenido remoto y cambios de terceros

Algunos scripts descargan contenido desde una dirección externa. Ese contenido puede cambiar después de que se publique la ficha, dejar de estar disponible o realizar acciones distintas a las que esperabas. Revisa la fuente actual y lo que descarga; evita ejecutar código cuyo comportamiento no puedas comprender.

Permisos, cuentas y datos personales

No pegues contraseñas, tokens, claves privadas ni datos de otras personas dentro de los scripts o las consultas de ayuda. Revisa cualquier petición de acceso a archivos, cuentas, red o información del dispositivo. Detente si un ejemplo te pide permisos que no tienen relación con su función.

Compatibilidad y reglas del entorno

Un Script de servidor y un LocalScript de Roblox Studio tienen responsabilidades diferentes. Los scripts para ejecutores externos tampoco son equivalentes a los de Studio. Revisa la ubicación de ejecución y las condiciones de la plataforma; el uso de herramientas externas puede incumplir sus normas y afectar a tu cuenta. Experimenta en proyectos propios o donde tengas autorización.

Pruebas y copias de seguridad

Evita probar código desconocido directamente en un proyecto publicado o con datos importantes. Haz una copia, utiliza datos de prueba y comprueba qué modifica el script. La compatibilidad puede variar según las versiones del lenguaje, las dependencias, el juego y el dispositivo.

Autoría y condiciones de reutilización

Consulta la licencia y las condiciones de la fuente original antes de redistribuir, vender o incorporar un ejemplo a otro proyecto. Mantén los créditos y avisos que correspondan. Que un código sea visible o fácil de copiar no significa que su autor haya autorizado cualquier uso.

05 / Sigue creando

Comparte lo que aprendes.

Si algo falla, reúne el enlace de la ficha, el lenguaje, el entorno, los pasos que seguiste y el mensaje de error exacto. Esa información ayuda mucho más que decir únicamente que un script no funciona. Antes de compartir una captura o un fragmento, elimina los datos privados.

Usa el centro de ayuda para consultar dudas habituales o reportar un problema. También puedes proponer ejemplos que te gustaría encontrar en la biblioteca. La idea de Rocío información es que tengas una referencia a la que volver: entender primero, probar con cuidado y crear cada vez con más autonomía.
