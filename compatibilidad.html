Dónde ejecutar cada grupo

Lua estándar: necesita un intérprete que exponga las bibliotecas base, math, string y table; algunos ejemplos también usan metatables o corrutinas. Los ejemplos no necesitan archivos, conexiones de red ni API privadas. Los ejemplos de texto que lo indican trabajan con ASCII o bytes.

Roblox cliente: coloca el código en un LocalScript dentro de StarterPlayer > StarterPlayerScripts de tu propia experiencia. Usa el modo de prueba de Studio. Los paneles usan tamaños relativos y los botones usan Activated para admitir clic, toque y mando. Esto no sustituye las pruebas reales en cada pantalla.

Roblox servidor: coloca el código en un Script dentro de ServerScriptService. Necesita acceso de edición a la experiencia. Un ejecutor cliente no proporciona autoridad del servidor. Las piezas creadas por estos ejemplos aparecen para los jugadores de esa sesión.

Las etiquetas PC y móvil del catálogo describen el destino del ejemplo, no el sistema en que se haya instalado un ejecutor. Roblox Studio se distribuye para Windows y Mac; puedes preparar allí la experiencia y probar el resultado en los clientes móviles. TouchEnabled detecta entrada táctil y no identifica Android o iOS.

Cómo comprobar un ejemplo

  1. Consulta la ubicación y los requisitos en la ficha del script.
  2. Ejecuta un ejemplo cada vez en una experiencia de prueba propia. Los de Lua se pueden probar en un intérprete aislado.
  3. Comprueba la salida y los errores. En Roblox prueba aparición del personaje, clic, toque y orientación de pantalla cuando corresponda.
  4. Registra modelo de celular, versión del sistema, versión de Roblox, ejecutor y resultado antes de afirmar compatibilidad.

Los loadstrings del catálogo anterior se mantienen sin verificar: descargan código que puede cambiar y no se ha comprobado su disponibilidad ni su contenido remoto. Los 200 ejemplos nuevos contienen su código completo.
